eli15 0.1.0-alpha.2

alpha.2 moves two status hues in the kit so every concept colour sits at least 30° from every status colour, up from 20° for the busy orange. It stops a before/after toggle from leaving its hidden side in the accessibility tree, and adds one test that runs the real gate, the real check and Chrome. The suite is now 10 tests.

Released 2026-10-29 as a pre-release. The diff covers 8260780..83dde17: 9 files, 88 lines added, 15 removed. Hue distances are computed from the oklch values in template.html before and after.

eli15 pages use two kinds of colour. A concept colour belongs to one idea on the page. A status colour (risk, warn, ok) means wrong, caution or right and nothing else. A colour's hue is its place on the wheel in degrees: 28 is red-orange, 90 yellow, 145 green, 252 blue, roughly.

alpha.1 asked concepts to stay 30° from risk only. Two pairs were still too close: busy and warn at 20° (60 against 80), and serve and ok at 28° (178 against 150). A reader who sees orange in a figure should not have to ask whether it means caution. alpha.2 moves the two status hues and leaves the template's four concept hues where they were, so pages copied from the template keep their colours.

Guidance: one rule with a number, four rules in words

The numeric rule is in visual-system.md: keep every concept hue 30° or more from every status hue, which are --risk 28, --warn 90 (dark 100) and --ok 145. What is left is 175° to 358°, plus one orange slot at about 60. That is room for five concepts: four hues 60° apart (175, 235, 295, 355) and the slot. Kit: two hues moved and a hidden toggle side leaves the accessibility tree

The hue move is two lines in template.html. Light-mode warn goes from 80 to 90, dark from 85 to 100. Ok goes from 150 to 145 in both. As a consequence, not as a stated reason, serve went from 28° to 33° away from ok.

-  --ok:   light-dark(oklch(52% 0.13 150), oklch(76% 0.13 150));
-  --warn: light-dark(oklch(60% 0.14 80),  oklch(82% 0.13 85));
+  --ok:   light-dark(oklch(52% 0.13 145), oklch(76% 0.13 145));
+  --warn: light-dark(oklch(60% 0.14 90),  oklch(82% 0.13 100));

The second kit change is one CSS declaration. A before/after toggle fades the state it hides with opacity. An opacity of 0 removes the pixels but leaves the group in the accessibility tree, so both states stayed in the tree. The hidden state now also turns visibility: hidden once the fade ends. alpha.1’s own release page had patched this in its page CSS; the kit now does it for every page.

Check: a demo word inside inline code no longer fails the page

check.py fails any page that still holds the template’s demo words. That also failed a page that only names them, such as a page about eli15 itself. The scan now deletes bare <code>…</code> spans before it looks. The change is +2 −1 in check.py.

✓ passes

✗ FAIL
The word in a sentence. The message: “template demo text left in the page”.
✗ FAIL
The word inside <code class="x">café</code>. Only a bare tag is skipped.

Gate: one test runs the whole chain for real

alpha.1 shipped 9 gate tests and none ran the real check.py: seven replaced it with a fake and two never reach it. Nothing proved that gate.py, check.py and Chrome work together. The tenth test does. It sends the JSON that Claude Code would send, in order, to the real gate.py. Step through it.

Key idea

The test checks the gate in both directions: a page that must be stopped is stopped, and a page that must pass passes. A gate that blocked everything would fail the second half; a gate that blocked nothing would fail the first.

On this Mac the template check took about 6 s and the whole pytest run about 12 s. The test skips when uv is missing, and also when the gate reports that it could not run the check, for example without Chrome. A skip is not a pass.

What this release does not do

  • No script enforces the hue rule. check.py has no rule for hue distance. The 30° rule is guidance Claude must follow, which is why the slider in Fig. 3 exists.
  • The toggle fix is not tested with a screen reader. It rests on how visibility works in CSS and on the kit’s own comment.
  • The new test needs Chrome and real time. On a machine without them it skips, so a green run there proves less.

Check what you took from this page

You can now say how much room the hue rule leaves

Guess firstIn light mode, risk is at hue 28 and warn at hue 90, 62° apart. A new concept hue must be 30° or more from both. How many whole-degree hues fit between them?

Show the answer

Three: 58, 59 and 60. From risk, the hue must be 28 + 30 = 58 or more. From warn, it must be 90 − 30 = 60 or less. Each status colour takes 30° out of the 62° gap, which leaves 2°. Most people guess a wide gap because 62° looks wide. Drag the marker in Fig. 3 from 55 to 65. In dark mode warn sits at 100, so the slot widens to 58 to 70.

A page names the template’s demo word in a sentence and again in a bare code span. What does check.py do?

It fails the page. The scan deletes the code span first, so the code span is fine, but the sentence still holds the word.

The new gate test runs on a machine with no Chrome. Does it fail?

No, it skips. The gate reports that the check could not run, and the test turns that report into a skip. With no uv it skips before anything runs.

Which lines of gate.py changed in this release?

None. The diff shows 0 lines for gate.py. The new test exercises the code that shipped in alpha.1.
