Release · first version of the plugin

eli15 0.1.0-alpha.1

eli15 stopped being one prompt. It is now a plugin with a page kit that has a slider, a stepper, a toggle and a guess box, a check that fails the old output on 4 rules, and a gate that runs the check before Claude may stop.

Released 2026-10-29 as a pre-release. The diff starts from the empty tree, because the repository had no commit before this one. Line counts are wc -l on the working tree.

Background

The old skill produced pages that were correct and flat

Guidance
SKILL.md and three reference files. What Claude reads to plan the page.
Kit
template.html: a finished page whose CSS and runtime Claude copies.
Check
check.py: source rules, a browser audit and screenshots of the page.
Gate
Hooks and gate.py: run the check before Claude may stop.

The old skill was three Markdown files, 438 lines in all. It asked for one accent colour, motion in CSS only and a script for nothing but the dark-mode toggle. Claude followed it. The page it produced was rejected: 13 sections with 13 drawings that never move, about 2,490 words of prose around about 630 words of drawing labels (roughly 190 prose words per figure), one button and nothing to drag, step through or guess.

Each of those traces to a rule in the old skill, not to the model. One accent colour left no hue per idea. CSS-only motion left no stepper. The skill's own reduced-motion snippet wrote 0.01 ms, a hack the new check rejects.

Watch out

Only 4 FAILs: the 0.01 ms hack, two missing kit markers and no interactive figure. One hue, text walls and drawings that never move only earn warnings or nothing. The check is the floor, not the bar, which is why the skill also makes Claude look at the screenshots.

SKILL.md is now a procedure of 99 lines. explainer-craft.md grew from 107 to 174 lines to hold the concept shapes, the ladder and the sentence rules. visual-system.md went from 223 to 186. motion-and-interaction.md is new at 194 lines: seven kinds of interaction, four URL parameters, reduced motion and print.

Kit: copy a finished page, never write the CSS

template.html is a finished 743-line page about coffee-shop queues that uses every component. Claude copies it and replaces the demo. The two parts that make every page behave the same stay untouched. Its runtime reads four URL parameters (?theme, ?motion=off, ?step, ?state), which is how the check opens every state of a page.

Check: a script reads the page, a browser audits it, you look

check.py is 383 lines. A FAIL must be fixed; a WARN is fixed or explained in the report. The phone view runs in a 390 px frame inside a 500 px window, because headless Chrome will not open narrower.

Gate: the check runs even when Claude forgets it

SKILL.md tells Claude to run the check. The gate makes sure it happened: hooks.json registers gate.py on three events, and gate.py is standard-library Python that remembers every eli15 page Claude writes and checks it at the next stop. Step through it.

Key idea

The gate is a net, not a wall. It blocks at most 3 times per page, then lets Claude through and tells the user. A broken check can slow a session down, never trap it.

Packaging

plugin.json (21 lines) carries the version, 0.1.0-alpha.1. The marketplace entry (15 lines) carries none, so an update arrives only when the version in plugin.json changes.

What this release does not do

  • The gate does not see shell writes. A page created with cat > page.html never reaches the hook, whose matcher is Write, Edit or MultiEdit. Claude must run the check itself.
  • The check has only run on macOS with Google Chrome. It also looks for Chromium or the path in $CHROME. Where it cannot run, the gate lets the stop through.
  • This is a pre-release. The install steps below come from the README and were not run for this page.

Moving from the standalone skill

Remove the old skill first, then install the plugin

Both copies would load: the plugin's as /eli15:eli15, the old one as /eli15. The bare /eli15 then keeps running the old copy, so the old one goes first. You need uv (brew install uv), Google Chrome and python3.

  1. Remove the standalone skill. On this Mac ~/.claude/skills is a symlink to ~/claude-config/skills, so this deletes a folder in that repository. Commit the removal there.

    rm -r ~/.claude/skills/eli15

  2. Give git your GitHub login. The repository is private. Without an SSH key, also set CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 before the next command.

    gh auth setup-git

  3. Add the marketplace.

    claude plugin marketplace add DresvyanskiyDenis/claude-eli15-plugin --scope user

  4. Install the plugin.

    claude plugin install eli15@claude-eli15-plugin --scope user

  5. Rename the override key. If skillOverrides in ~/.claude/settings.json has a key "eli15", change it to "eli15:eli15". The value, for example "user-invocable-only", stays.

  6. Reload. Run /reload-plugins in Claude Code, or restart it. The command is now /eli15:eli15 <topic>, not /eli15.

Later updates: claude plugin marketplace update claude-eli15-plugin, then claude plugin update eli15@claude-eli15-plugin.

Check what you took from this page

You can now say what the gate does when a page keeps failing

Guess firstClaude's fixes do not help: the same page fails the check at four stops in a row. What happens at the fourth stop?

Show the answer

It goes through and the user is told. Stops 1 to 3 are blocked. At the fourth, gate.py drops the page from its list and shows a message that the page still fails after 3 fixes, with the command to run by hand.

Claude writes a page with cat > page.html in the shell. Does the gate check it?

No. The PostToolUse matcher is Write, Edit or MultiEdit, so a shell write never reaches the pending list. SKILL.md still tells Claude to run check.py itself.

uv is not installed and Claude stops twice. What does the user see?

A message each time that pages were not checked, and no block. The pages stay on the pending list, so the second stop warns again.

After installing the plugin, which key in settings.json must change, and to what?

The skillOverrides key "eli15" becomes "eli15:eli15": the plugin's skill is named plugin:skill.
